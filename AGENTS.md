# AGENTS.md

## Project Overview

Multi-tenant CRM for Market Bytes (digital marketing agency). Ingests Meta (Facebook) Lead Ads via webhook, routes leads to isolated per-client portals using PostgreSQL Row-Level Security (RLS).

**Stack:** FastAPI + SQLAlchemy 2.0 + Celery/Redis backend; Next.js 16 + React 19 frontend; PostgreSQL 16 with RLS.

## Architecture

- **Tenant isolation:** PostgreSQL RLS via `SET LOCAL app.current_tenant_id` — not app-level filtering. Every tenant-scoped table needs both a `client_id`/`organization_id` column and an RLS policy.
- **DB roles:** `app_service` (BYPASSRLS) for webhook receiver, Celery workers, migrations, auth lookups. `app_client` for regular tenant-facing API routes via `get_tenant_db`.
- **Data flow:** Meta webhook → HMAC verify → Celery queue → Graph API fetch → `page_id`/`form_id` → `organization_id` mapping → DB write (RLS-scoped) → portals.
- **Frontend portals:** `/superadmin` (agency staff), `/client` (client admin), `/rep` (sales rep). All share one default UI — no per-client branding.

## Setup

```bash
# 1. Start infrastructure
docker compose up -d

# 2. Backend setup
cd backend
python -m venv venv
source venv/bin/activate  # Windows: .\venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env
python seed_db.py

# 3. Frontend setup
cd ../frontend
npm install
```

## Running

```bash
# Terminal 1: Backend API (from backend/)
uvicorn app.main:app --reload --port 8000

# Terminal 2: Celery worker (from backend/)
# Windows:
celery -A app.workers.celery_app worker --loglevel=info -P solo
# Linux/macOS:
celery -A app.workers.celery_app worker --loglevel=info

# Terminal 3: Frontend (from frontend/)
npm run dev
```

## Key Conventions

- **Backend:** SQLAlchemy 2.0 `Mapped[...]` style, Pydantic v2 with `from_attributes=True`. One shared `app/models/models.py` for both API and Celery worker.
- **Frontend:** Next.js App Router, TypeScript, Tailwind CSS v4, React Query, Zod validation. API calls via `lib/api/httpClient.ts` (base URL: `http://localhost:8000/api`).
- **Auth:** JWT (HS256), 24h expiry. Token stored in localStorage as `marketbytes_token`.
- **Migrations:** Alembic. `alembic revision --autogenerate -m "msg"` then `alembic upgrade head`.

## Critical Rules

- **Never bypass webhook signature verification** (`X-Hub-Signature-256`) — not even for debugging.
- **Never disable RLS** or write cross-tenant queries outside the designated service-role paths.
- **Never commit `.env`** or real credentials.
- **Never use `app_service` role** for regular tenant-facing API routes.
- **Webhook receiver must stay fast** — only verify signature and enqueue to Celery, no DB writes or Graph API calls.
- **Form data is inconsistent across clients** — only `name`, `phone`, `email` are guaranteed; everything else goes in `form_answers` JSONB.
- **A client can have multiple simultaneous campaigns/forms** — never assume 1:1 client-to-page or client-to-form.
